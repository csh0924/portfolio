00 / OVERVIEW

빠른 탐지와
깊은 상황 이해의 결합

04 / ON DEMANDVLM Analysis

상황 악화 시에만 호출

WHY / 01

Detection만으로 부족한 맥락

불꽃과 연기를 빠르게 찾을 수 있지만 요리 연기, 조명, 화재 원인과 주변 위험 요소까지 판별하기 어렵다.

WHY / 02

VLM 단독 처리의 비용

상황 이해는 우수하지만 모든 CCTV Frame을 분석하면 응답 지연과 GPU·API 비용이 증가한다.

DESIGN / 03

조건부 결합

YOLO가 후보를 넓게 보존하고, 상황 변화가 감지된 사건만 VLM이 재검증해 각 모델의 장점을 필요한 지점에 사용한다.

Azure AI Foundry 기반 VLM에 연속 Frame, YOLO의 Label·Score·Bounding Box와 CCTV 위치·시간 정보를 함께 전달했다.

CASE A / FALSE ALARM

연기 감지 → 신고 차단

YOLO는 연기를 후보로 탐지했지만, VLM은 주변 맥락을 조리 상황으로 판단하여 신고 문구를 생성하지 않았다.

CASE B / REAL FIRE

화재 감지 → 위험 상황 분석

화염과 연기의 확산, 주변 공간을 종합해 실제 화재로 판단하고 위험도와 긴급 신고 초안을 생성했다.

구조화와 관찰 가능성의 균형

초기 Prompt는 정의된 JSON Field만 반환해 Schema 밖의 잠재 위험 요소가 누락됐다. 정형 Field의 일관성을 유지하면서 모델이 발견한 특이사항과 추정 원인을 기록할 수 있도록 additional_observation 영역을 추가했다. 오탐 판단 시 신고 문구를 비우는 Guardrail도 함께 적용했다.

07 / REVIEW

Technical Review
& Significance

기존 컴퓨터비전 프로젝트에서 직접 학습한 모델로 시각적 특징을 검출·분할했다면, Burinake에서는 VLM을 도입해 이미지의 주변 맥락과 시간적 변화까지 해석 범위를 확장했다. 그러나 VLM을 단순히 추가하는 데 그치지 않고, 기존 Detection 모델과 VLM이 가진 서로 다른 강점과 비용을 분석해 역할을 분리했다.

YOLOv12는 실시간 후보 탐지에 집중하고 VLM은 선별된 사건의 진위와 위험도를 해석한다. 빠르지만 맥락이 제한적인 기존 딥러닝 모델과, 풍부한 상황 이해가 가능하지만 느리고 비용이 큰 VLM을 조건부 Cascade로 결합함으로써 최신 모델이 기존 모델을 대체하는 것이 아니라 상호 보완할 수 있음을 확인했다.

동일 CCTV의 반복 탐지를 Issue로 병합하고 상황 악화 시에만 VLM을 재호출하는 정책까지 포함하며, 모델 정확도뿐 아니라 Latency, 처리 비용과 알림 품질을 함께 고려하는 AI 서비스 설계 경험을 확보했다.

현재는 테스트 이미지 기반 Demo로, 실제 CCTV Stream과 소방 신고 시스템은 연결되지 않았다. 운영 단계에서는 동시 요청에서의 VLM 처리량·비용 측정, 실제 현장 데이터 평가와 화재 Domain에 특화된 VLM 검증이 필요하다.
