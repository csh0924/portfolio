CASE 03 AI · COMPUTER VISION 2025. 09 — 2025. 12

Korean Handwriting Analysis

바른글씨:
바람

손글씨 문장을 문자와 자소 단위로 분해하고, 형태·위치·자간·크기·기울기를 분석하여 맞춤형 교정 피드백을 제공하는 딥러닝 기반 서비스.

00 / OVERVIEW

첫 엔드투엔드
딥러닝 파이프라인

문제 정의와 데이터 생성부터 모델 설계·학습, 후처리, Python 분석 서버 구현까지 전 과정을 직접 수행한 첫 AI 프로젝트. CRAFT의 문자 중심 확률과 기하학 알고리즘을 결합해 문자를 분리하고, FPN 모델로 초성·중성·종성을 픽셀 단위로 분석했다.

Period
2025. 09. 01
— 2025. 12. 31
Team
3명
Role
AI Model Training
Python Server
Dataset
51,138
Labeled Images

01 / PIPELINE

문장에서 자소까지
역순으로 분해

문장 정규화 → CRAFT 중심 추출 → Voronoi 문자 분리 → FPN 자소 Segmentation → 형태·위치 평가 → 점수 및 피드백 생성.

02 / CONTRIBUTION

Owned Scope

데이터 설계부터 모델 학습과 서비스 연동까지 이어지는 AI 개발 범위.

01

데이터셋 구축

실사용 한글 2,841자와 6개 폰트, 3종 Augmentation을 조합해 51,138개의 Label 데이터 자동 생성.

02

FPN 모델 학습

한글 구조를 6개 유형으로 분류하고 유형별 FPN 모델을 학습하여 초성·중성·종성 Segmentation 수행.

03

손글씨 분석 설계

CRAFT 문자 중심 추출, 문장 기울기·자간 분석, Voronoi 기반 문자 분리와 연결 성분 Reclaim 후처리 구현.

04

Python 분석 서버

전처리부터 점수 생성까지 분석 모듈을 연속 실행하고 결과 JSON과 이미지 경로를 서버에 반환하는 파이프라인 관리.

05

LLM 피드백 생성 공동 수행

정량화된 자소 형태·위치 및 문장 분석 점수를 Gemini API에 전달하고, 사용자가 이해할 수 있는 교정 가이드로 변환하는 피드백 구조 공동 설계.

03 / RESEARCH DESIGN

한글 구조를 반영한
분석 문제 설계

일반적인 문자 인식이 아니라 손글씨의 구조적 완성도와 시각적 정렬성을 정량화하는 문제로 정의했다.

QUESTION / 01

연결된 손글씨에서 개별 문자를 어떻게 분리할 것인가?

Approach
CRAFT 문자 중심 확률 맵에서 중심 좌표를 추출하고, 글자 수와 예측 중심 수를 비교해 과검출 중심을 병합.

QUESTION / 02

11,172개 한글의 자소 Label을 어떻게 확보할 것인가?

Approach
실사용 2,841자를 선별하고 한글 조합 원리에 따라 237개 기준 문자에서 자소를 추출하여 합성 데이터 자동 생성.

QUESTION / 03

서로 다른 한글 자소 배치를 어떻게 안정적으로 학습할 것인가?

Approach
종성 유무와 모음 방향을 기준으로 여섯 유형을 정의하고 유형별 FPN을 학습해 단일 모델의 구조적 부담을 분리.

04 / DATASET ENGINEERING

한글 조합 원리로
Label을 생성

모든 완성형 문자를 수작업으로 Labeling하는 대신, 한글의 초성·중성·종성 조합 규칙을 데이터 생성 알고리즘으로 전환했다.

11,172표현 가능한 한글
2,841말뭉치에서 선별한 실사용 문자
237직접 Labeling한 기준 문자
51,138최종 생성 Label 이미지
  1. 01

    실사용 문자 선별

    AI Hub 한국어 말뭉치 약 29억 자의 등장 빈도를 분석해 전체 11,172자 중 실제 사용된 2,841자를 학습 대상으로 축소.

  2. 02

    구조 유형 분리

    종성 유무 2종과 모음 형태 3종을 조합해 한글 배치를 6개 유형으로 분류하고 유형별 좌표 체계를 유지.

  3. 03

    자소 Component 추출

    237개 기준 문자에서 일부 영역을 Masking하여 형태와 위치 정보를 함께 가진 초성·중성·종성 Component 확보.

  4. 04

    조합 및 증강

    2,841자 × 나눔손글씨 6폰트 × 위치·크기 변형 3종을 조합하여 51,138개의 Pixel Label 데이터 생성.

05 / CRAFT DETECTION

문자 검출 모델을
중심점 추출기로 활용

CRAFT의 본래 단어 영역 검출 결과를 그대로 사용하지 않고, 문자 중심일 확률이 높은 픽셀의 무게중심을 각 글자의 기준점으로 사용했다.

01

중심 후보 추출

임계치 이상의 Region Score 픽셀을 묶고 각 영역의 무게중심을 문자 중심 후보로 계산.

02

과검출 보정

입력 원문의 글자 수보다 중심 후보가 많으면 인접 후보를 병합해 문자 수와 일치시킴.

03

분석 기준 생성

중심 간 기울기와 x축 거리를 문장 기울기·자간 분석에 사용하고, 문자 영역 확장의 Seed로 전달.

06 / CHARACTER SEPARATION

중심점에서 확장하고
연결 성분으로 재할당

CRAFT로 추출한 문자 중심을 Seed로 Voronoi 영역을 생성한 뒤, 서로 연결된 픽셀은 같은 글자일 가능성이 높다는 가정으로 Label을 보정했다. 단, 획이 맞닿는 손글씨에서는 이 가정이 항상 성립하지 않는다.

07 / SEGMENTATION

초·중·종성
Pixel Segmentation

여러 해상도의 특징을 결합하는 FPN 구조로 자소를 분리하고 인쇄체 Segmentation을 기준으로 결과를 보강했다.

RESULT / 01

유형별 6개 모델 학습

종성 유무 2종과 모음 형태 3종을 조합해 모델이 처리해야 할 한글 배치 복잡도를 분리했다.

RESULT / 02

정성 결과와 오류 확인

‘캡스톤디자인’ 문장의 자소 분할을 시각화했다. 일부 글자의 오분류도 함께 확인하여 후처리 보강의 필요성을 도출했다.

RESULT / 03

Segmentation 후처리

선택한 인쇄체의 자소 Label을 Seed로 약한 클러스터링을 수행하고, 하나의 연결 성분에 섞인 소수 Label을 다수 Label로 통일하여 경계 오분류를 보강했다.

08 / DEMO

End-to-End
Service Demo

손글씨 작성부터 분석 결과와 항목별 교정 피드백을 확인하는 전체 서비스 흐름.

09 / REVIEW

Technical Review
& Significance

정제된 데이터와 준비된 모델이 제공되는 학습 환경에서 벗어나, 불완전한 데이터와 예외가 존재하는 현실적인 조건에서 처음 수행한 AI 프로젝트다. 문제 정의, 데이터셋 생성, 모델 학습, 후처리 및 서비스 연동까지 직접 연결하며 실제 AI 개발 과정의 불확실성을 경험했다.

한글의 조합 원리를 데이터 설계에 반영하고 CRAFT·FPN·기하학적 후처리를 하나의 분석 파이프라인으로 완성한 경험은 컴퓨터비전 문제를 독립적으로 설계하고 구현할 수 있다는 확신으로 이어졌다. 이 프로젝트를 기점으로 이후 두 프로젝트 또한 컴퓨터비전 중심의 딥러닝 연구로 확장했다.

합성 과정에서 일부 가로형 중성과 종성이 겹치는 문제가 남았다. 모음 분류 체계를 세분화하고 Label 중첩을 감지해 위치를 조정하는 방식이 후속 개선 과제다.
